# F2: Персистентность сообщений и пагинация — Дизайн

> Дата: 2026-03-08
> Статус: утверждён
> Зависимости: F1 (стриминг) должен быть реализован до F2

## Контекст

Сервер — источник истины для сообщений (Mastra memory). Фронтенд только отображает и отправляет пользовательский ввод. Сейчас загружаются все сообщения одним запросом (`perPage: 1000`). Нужна пагинация и корректная загрузка истории.

Observational memory сжимает старые сообщения, поэтому очень длинных историй не будет, но пагинация всё равно нужна для корректной работы.

## Scope

- Пагинация сообщений (загрузка последних 50, кнопка "загрузить ранние")
- Удаление истории — НЕ входит в F2, делается в F8

## Решения

- **Подход:** серверная пагинация через `page`/`perPage` (нативная поддержка Mastra API)
- **Размер страницы:** 50 сообщений
- **UI подгрузки:** явная кнопка "Загрузить ранние" вверху списка (не infinite scroll)

## Бэкенд

### Изменения в `/api/chat/messages/route.ts`

Расширение существующего эндпоинта (не новый).

**Параметры запроса:**
- `chatId` (обязательный) — как сейчас
- `page` (опциональный, дефолт `0`) — номер страницы
- `perPage` (опциональный, дефолт `50`, максимум `100`)

**Вызов Mastra:**
```typescript
thread.listMessages({
  page,
  perPage,
  orderBy: { field: 'createdAt', direction: 'DESC' }
})
```

Загрузка DESC (новые первыми), page=0 — последние 50. Перед отдачей клиенту — реверс в ASC (хронологический порядок).

**Ответ:**
```json
{
  "messages": [],
  "hasMore": true
}
```

**Валидация:**
- `page`, `perPage` — parseInt, дефолты при невалидных значениях
- `perPage` ограничен максимумом 100
- Авторизация и ownership check остаются как есть

## Фронтенд

### Хук `use-chat-messages.ts`

Замена `useQuery` на `useInfiniteQuery` из react-query:

- **Первый запрос:** `page=0` — последние 50 сообщений
- **"Загрузить ранние":** `fetchNextPage()` → page=1, page=2...
- **Данные:** все страницы склеиваются в один массив в хронологическом порядке (ранние в начало)
- **`hasMore`** из ответа API определяет видимость кнопки

**Экспорт хука:**
```typescript
{ messages, isLoading, hasMore, fetchOlderMessages, isFetchingOlder }
```

### Интеграция с useChat (после F1)

1. `useChatMessages` загружает историю (page=0)
2. Результат передаётся как `initialMessages` в `useChat`
3. Новые сообщения из стрима добавляются автоматически
4. "Загрузить ранние" — prepend к списку сообщений

### UI — кнопка "Загрузить ранние"

В `message-list.tsx` вверху списка:
- Видна только когда `hasMore === true`
- При нажатии — `fetchOlderMessages()`, показывает спиннер
- После загрузки скролл остаётся на том же месте

### Сохранение позиции скролла

При prepend старых сообщений:
- Запомнить `scrollHeight` до вставки
- После вставки: `scrollTop += newScrollHeight - oldScrollHeight`

## Граничные случаи

| Случай | Поведение |
|--------|-----------|
| Пустой чат | `messages: [], hasMore: false`, UI: "Send a message to start" |
| < 50 сообщений | Все загружены на page=0, `hasMore: false`, кнопка скрыта |
| Перезагрузка страницы | Загружается page=0, ранее подгруженные страницы теряются |
| Новые сообщения во время просмотра старых | Стрим добавляет в конец, не конфликтует с prepend |
